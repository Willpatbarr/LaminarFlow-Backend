# Change documents

One pair of files per ticket: a markdown record of every change with its
reasoning, and a standalone HTML version of the same content with syntax
highlighting and tab navigation.

These are a record of *why* a change was made and what was decided against, at
the moment it was made. They are not maintained afterwards — a change document
describes the ticket that produced it, not the current state of the code. Read
`docs/adr/` for decisions that are still in force, and the code for what it does
now.

The HTML file is self-contained: no network, no build step. Open it directly.
